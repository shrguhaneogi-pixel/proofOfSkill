# Tech Stack

<VERSION_POLICY>
- Do not pin versions from this file. Resolve versions from the repo first (`package.json`, `Cargo.toml`, `anchor --version`, `solana --version`), then from the registry (`pnpm view <pkg> version`) for new installs.
- Use the current stable major of each tool. Never downgrade an installed major to match a tutorial.
- The `anchor-lang` crate version, the Anchor CLI version and the TypeScript Anchor client version must match on major.minor. Verify with `anchor --version`, `Cargo.toml`, and the client's `package.json`.
- Record resolved versions in `docs/living-notes.md` → `## Resolved Versions`.
</VERSION_POLICY>

<ALLOWED_DEPENDENCIES>
Frontend:
- `next` (App Router only), `react`, `react-dom`, `typescript` (strict)
- `tailwindcss` v4 (CSS-first), `@tailwindcss/postcss`, shadcn/ui via `pnpm dlx shadcn@latest`, `lucide-react`, `clsx`, `tailwind-merge`, `class-variance-authority`, `tw-animate-css`
- `motion` (Framer Motion's current package; import from `motion/react`)
- `three`, `@react-three/fiber`, `@react-three/drei` — hero only, lazy-loaded
- `zod` (validation), `server-only`, `bs58`
- AI: `openai` SDK pointed at any OpenAI-compatible endpoint (configurable base URL)
- Tests: `vitest`

Solana client:
- `@solana/web3.js` v1.x — kept because `@solana/wallet-adapter-*` and the Anchor TS client are built on it. It is the library-required transport layer. Isolate all usage in `lib/solana/` and do not mix in `@solana/kit` in the same module graph.
- `@solana/wallet-adapter-base`, `-react`, `-react-ui`
- Anchor TS client: check `pnpm view @anchor-lang/core version`. If it exists and matches the installed Anchor CLI line, use it; otherwise use `@coral-xyz/anchor` at the matching version. Log the decision.

Program:
- Rust, `anchor-lang` (matching CLI). Add `anchor-spl` only if Token-2022 is explicitly approved (it is not in the MVP).

NOT allowed without a written justification in `docs/living-notes.md`: GSAP, any database/ORM, Redux, Zustand, axios, moment, styled-components, additional wallet adapters beyond what the wallet stack provides.
</ALLOWED_DEPENDENCIES>

<COMMANDS>
Use `package.json` scripts; create them if missing:
- `pnpm dev` — Next.js dev server
- `pnpm build` — production build
- `pnpm typecheck` — `tsc --noEmit`
- `pnpm lint` — run the linter CLI directly (e.g. `eslint .`); do not use `next lint` (removed in current Next.js)
- `pnpm test` — `vitest run`
- `anchor build` — build program + IDL
- `anchor test` — localnet integration tests
- `anchor keys list` / `anchor keys sync` — program ID management
- `anchor deploy --provider.cluster devnet` — only when wallet funded and `solana config get` shows devnet
After `anchor build`, copy `target/idl/proof_of_skill.json` and `target/types/proof_of_skill.ts` into `lib/solana/idl/`. Never hand-edit these copies.
</COMMANDS>

<API_PITFALLS>
Use the right-hand column. Verify against installed versions when in doubt.

| Area | Do not use | Use |
|---|---|---|
| Next.js | `next lint`; sync `params`/`searchParams`/`cookies()`/`headers()`; `pages/` router; `middleware.ts` if the installed major renamed it to `proxy.ts` | ESLint CLI; `await params` (typed `Promise<{...}>`); async request APIs; App Router; the filename the installed major expects |
| Next.js | `ssr: false` in `next/dynamic` inside a Server Component | wrap in a small `"use client"` component, then `dynamic(() => import(...), { ssr: false })` |
| Tailwind | `tailwind.config.js` + `@tailwind base/components/utilities`; `tailwindcss-animate` | `@import "tailwindcss";` in `globals.css`, tokens in `@theme`; `tw-animate-css` |
| shadcn | copying old snippets with `forwardRef` / `React.ElementRef` blindly | components generated by the installed CLI |
| Motion | `framer-motion` import path | `import { motion, useReducedMotion } from "motion/react"` |
| R3F | v8 patterns with React 19 | `@react-three/fiber` major that supports installed React; `Canvas` in a client component; `frameloop="demand"` when static |
| Wallet | `PhantomWalletAdapter` registered manually as the default path | `WalletProvider wallets={[]}`; Phantom and others are discovered via Wallet Standard. Add explicit adapters only if detection fails and log it |
| Wallet | `@solana/wallet-adapter-wallets` mega-package | not installed |
| Web3.js | `Transaction` + `recentBlockhash` legacy flow for new code; `sendAndConfirmTransaction` in the browser | `VersionedTransaction` with `TransactionMessage(...).compileToV0Message()`; `wallet.sendTransaction`; `connection.confirmTransaction({ signature, blockhash, lastValidBlockHeight }, "confirmed")` |
| Web3.js | `confirmTransaction(signature)` (string-only form) | the blockhash-strategy object form above |
| Web3.js | `VersionedTransaction.partialSign(signers)` — **does not exist** in 1.99.0 (only legacy `Transaction` has it; verified in `lib/index.d.ts`) | `transaction.sign([issuer])`: on a `VersionedTransaction` it signs only the slots it is handed and leaves the rest zero, which *is* the partial sign the wallet then completes |
| Web3.js | `new Connection(url, { confirmTransactionCommitment })` (a `@solana/kit` field) | `new Connection(url, { commitment })` |
| Web3.js | `clusterApiUrl("localnet")` — not a valid `Cluster` | `http://127.0.0.1:8899` for localnet |
| Web3.js | passing `Uint8Array` as `TransactionInstruction.data` | `Buffer.from(bytes)` — and keep that module server-side, since the browser bundle has no `Buffer` |
| Anchor (Rust) | `ctx.bumps.get("name")`; `init_if_needed`; manual space math | `ctx.bumps.name`; plain `init`; `#[derive(InitSpace)]` + `space = 8 + Type::INIT_SPACE` |
| Anchor (Rust) | `msg!` as the event mechanism | `#[event]` + `emit!` |
| Anchor (TS) | `anchor.setProvider` in app code; `Program` constructed with `(idl, programId, provider)` | `new Program(idl, provider)` — program address comes from the IDL `address` field |
| Anchor (TS) | `.rpc()` for wallet-adapter flows | `.instruction()` to get the instruction, compose into a `VersionedTransaction` |
| Clock | `Clock::from_account_info` | `Clock::get()?` |
| Zod | v3-only idioms if v4 is installed | check installed major; use `z.object({...}).safeParse` |
| React | `useEffect` for data that a Server Component can fetch | fetch in Server Components; `use`/Suspense where appropriate |
| Crypto | `crypto-js`, `js-sha256` | Node `node:crypto` on server, `crypto.subtle` in browser |

When this table and the installed package disagree, the installed package wins; record the discrepancy in `docs/living-notes.md`.
</API_PITFALLS>

<ANCHOR_WORKSPACE_NOTES>
- Anchor and Next.js share the repo root. Keep TypeScript configs separate: root `tsconfig.json` excludes `tests/` and `target/`; `tests/tsconfig.json` is CommonJS-friendly. Point the `[scripts] test` entry in `Anchor.toml` at it with the test runner's `-p tests/tsconfig.json` flag (verify the runner flag with `--help`).
- Program ID: generate with `anchor keys list`, sync with `anchor keys sync`, and write the real ID to `NEXT_PUBLIC_PROGRAM_ID` only after build. Never invent one.
- Devnet RPC: public RPC is rate-limited; allow `NEXT_PUBLIC_SOLANA_RPC_URL` override.
</ANCHOR_WORKSPACE_NOTES>
